# Brail Recorder — Security & Privacy Architecture

## 1. Zero Cloud Dependency & Offline First

Brail Recorder is strictly designed as a local-first utility:
- **No User Accounts**: Does not require user registration, logins, or authentication tokens for local recording.
- **Direct Streaming Only**: All live streaming connections originate directly from the host machine to the user-specified ingest point (e.g. `rtmp://a.rtmp.youtube.com/live2`). No traffic routes through intermediate proxy servers.
- **Zero Telemetry / Analytics**: User activity, recording filenames, screen contents, microphone feeds, and crash logs are never uploaded to remote tracking endpoints.

---

## 2. Windows DPAPI Credential Storage

Sensitive user credentials — specifically YouTube and RTMP stream keys — are protected at rest using the **Windows Data Protection API (DPAPI)**:
```rust
CryptProtectData(
    &mut secret_blob,
    None,
    Some(&mut entropy_salt),
    None,
    None,
    0,
    &mut encrypted_blob
);
```
- **Hardware/User-Bound Keys**: Secrets are encrypted using symmetric keys generated by Windows and tied directly to the current Windows user login security descriptor.
- **Protected at Rest**: Config files stored on disk (`%APPDATA%\BrailRecorder\config.json`) contain only the binary ciphertext bytes (`stream_key_encrypted`), ensuring unauthorized read access to config files reveals no credentials.

---

## 3. Log Redaction & Secret Masking

- All tracing subscribers and error reporting utilities employ an automated regex redaction engine (`SecureVault::redact`).
- Any string containing detected stream keys, authorization headers, or common key formats (such as YouTube's `xxxx-xxxx-xxxx-xxxx-xxxx`) is replaced with `[REDACTED_STREAM_KEY]` prior to being written to stdout or rotating log files.
- UI password fields display masked dots (`●●●●●●●●●●●●`) by default, with an explicit show/hide toggle.
